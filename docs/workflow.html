Pocket Queue / Documentation / Workflow
Operator journey

One queue, one clear flow.

The application keeps every operational decision close to the queue screen. Destructive actions confirm before changing the local record.

First launch

1. Welcome

Choose Get Started for guided setup, or View Demo to load a realistic local queue immediately.

2. Business setup

Enter business name, counter name, and operator name. The values appear on the queue header and display screen.

3. Queue configuration

Choose a prefix, starting number, maximum number, and auto-reset mode. The default numbering is A-001 onward.

Generate a queue number

Tap Add Queue Number to open a bottom sheet. Choose Regular, Priority, or Appointment and select a quantity from one to ten. Priority tickets use a P prefix; appointment tickets use a T prefix. Active duplicate numbers are prevented before a ticket is stored.

Regular      A-001, A-002, A-003
Priority     P-004, P-005
Appointment  T-006

Call next and announcement

The primary action is CALL NEXT. It is disabled when the queue is paused, another ticket is serving, or no waiting ticket exists. The app updates the local record immediately and the display screen reflects the current ticket through the shared store.

Empty-state behavior: when no ticket is waiting, the queue screen shows an em dash and asks the operator to generate a number. There is no fake call or hidden state.

Display mode

Open Display from the bottom navigation, navigation rail, or queue header fullscreen button. The display uses high-contrast dark styling with business name, current ticket, counter, next three tickets, date, and time. Settings control which optional date, clock, and next-ticket elements appear.

History and statistics

History contains completed and skipped records. Each row opens Queue Detail with creation, call, start, completion/skip, waiting duration, and service duration. Statistics summarize generated, served, skipped, waiting, average waiting, average service, longest waiting, busiest hour, and hourly served bars.

Reset and data safety

Reset Queue and Reset Application require confirmation dialogs. Delete History removes only completed and skipped records. Reset Application clears local records and returns to onboarding. Export CSV uses the platform share flow and includes queue number, status, timestamps, waiting minutes, and service minutes.
